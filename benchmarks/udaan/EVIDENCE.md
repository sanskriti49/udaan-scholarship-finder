## Existing claims and architecture checked

The React/Vite frontend exposes catalogue filters, eligibility results with rule explanations/evidence, saved scholarships, alert preferences and scanner review. MongoDB models separate stable schemes, academic-year cycles, immutable source snapshots, change history, eligibility rule versions, profiles, bookmarks, notification preferences/logs and delivery receipts. Unique indexes protect source snapshots `(url,textHash)`, scheme identity, bookmark pairs, rule-version keys, notification dedup keys and eligibility delivery `(user,scholarship,version)`. Mongoose writes are per-document operations; there is no claim of a cross-collection transaction for an entire crawl.

The pipeline distinguishes document-text changes from normalized scholarship changes, reuses matching snapshots, stores evidence offsets, preserves unavailable records, and supports source-specific adapters and authority tiers. Current browser support was exercised; current live government/private portal coverage was not. Recorded official NSP captures are dated 17 September 2026 and are test evidence, not a fresh October crawl.

The eligibility engine reports pass/fail/unknown, does not invent missing values, and flags additional unrecorded criteria for manual review. Rule-change alerts compare old/new versions against the **same saved profile**, require opt-in/bookmarks and evidence, and suppress unchanged/unavailable/superseded events. Database-level deduplication is defensible for inbox records; **exactly-once external email is not**. Reminder enqueue can skip work when Redis is unavailable; permanent eligibility pending events have a relay/recovery path. Redis data persistence across a Redis-server loss was not tested; worker downtime/restart was.

The scanner supports local English PDF/PNG/JPEG, file signature/size/page/pixel limits, native PDF text before OCR, cancellation/worker cleanup and editable extracted evidence. `verifiedRules` is empty: it does **not** authenticate certificates or certify scholarship-specific compliance. No general OCR accuracy percentage, multilingual coverage, arbitrary scans or exhaustive device performance is claimed.

Security source review confirmed password hashing with bcrypt, Bearer JWT authorization, role-gated crawler/cache administration, Turnstile checks on password login/register, crawler host/robots/GET/request-budget controls, escaped regex fallback, and safe scanner source URLs. The actual admin cache route returned 401 without credentials. This is not a penetration test: live Google/Turnstile/SMTP were not exercised. Google login delegates to Google userinfo/tokeninfo endpoints without an explicit audience check in the inspected handler; CORS permits broad Vercel/Render origins, and the limiter trusts `X-Forwarded-For` directly. No blanket production-hardening claim is made.

## Confirmed limitation left unchanged

[API contract reproduction](C:/Users/sansk/Downloads/udaan-scholarship-finder/benchmarks/udaan/results/api-contracts.json) confirms that `level=UG` and `level=ug` share the lowercased Redis cache key while the controller's filter is case-sensitive. With a primed cache, the lowercase request returned 104 total schemes; without caching it returned 0. Reordered valid query parameters correctly reused a cache key, and an actual database update followed by invalidation returned updated content. The k6 workload used canonical valid filters, so this finding does not invalidate those measurements. It does prevent claiming cache correctness for all input variants. Production code was left unchanged in accordance with the requested audit/resume scope.

## Increment 2: internal durable execution

Implemented using pinned `@langchain/langgraph` and `@langchain/langgraph-checkpoint` dependencies, with the existing native MongoDB driver supplied by Mongoose:

- A single coordinating graph: model → one research tool at a time → model, with an interrupt for optional clarification. No agent swarm, hosted LangGraph server, extra Python service, Redis worker or vector database is needed.
- An internal `createDurableNavigator` service exposing `start`, `get`, `advance` and `cancel`. Each advancement executes at most one new model call, checkpoints synchronously, and releases its lease. A later advancement continues the saved graph. There is no unattended background execution.
- Run ownership, strict input contracts, idempotent starts, one active run per owner, expected revisions, a 60-second execution lease and a default 40-second advancement deadline. A new worker can reclaim an expired lease. Run, checkpoint, pending-write and accounting writes all check the current lease token in MongoDB; a stale worker cannot overwrite its successor.
- Persistent global/provider and per-user daily call reservations, with MongoDB's UTC clock and atomic conditional writes. A run's lifetime model/tool budgets survive resumes, restarts and daily resets. Reservations happen before inference. Missing storage or exhausted quotas prevent inference; ambiguous attempts stay charged, including requests whose provider usage is unknown. There are no automatic provider retries or fallback models.
- A bounded MongoDB checkpointer stored within the owned run document, keeping three full checkpoints plus bounded task writes. Task writes may arrive before checkpoint creation; they are buffered under the same fence. This saver supports this graph's single root namespace and full-state channel, not arbitrary subgraphs, branching histories, delta channels or time travel.
- Private selected profile inputs stored separately from graph state, model messages and public run responses. Clarification answers and an opaque resume choice are accepted atomically; recovery cannot lose the choice after accepting the answers. Matching runs again after either answering or skipping. Skipped inputs stay unknown.
- Cancellation, partial/quota/interrupted states, actual tool-event sequences, provider-reported token totals and an explicit incomplete-usage flag. Ambient LangSmith tracing is refused when enabled. The provider/model is pinned for the run; changing it requires a new investigation.
- Seven-day run retention by default (bounded to 1–14 days), server-clock expiry and a TTL index. Expired runs cannot be read or advanced even before MongoDB's asynchronous TTL deletion. Completion and cancellation immediately clear private profile inputs and checkpoints. Completed research results remain in the owned run until expiry; explicit user-confirmed saved plans are a later feature.

The durable module has no import-time connections or inference. Increment 3 now initializes it from the existing Express server after MongoDB connects, creates its indexes, and mounts authenticated HTTP endpoints. Authentication supplies every owner ID; endpoints never accept owners from a request body.

The run and quota collections are `navigator_runs` and `navigator_quotas`. Quotas are deployment-wide for each provider in this database; separate database deployments do not share a budget. Keep keys/backend settings consistent across replicas. These application call limits supplement a provider's account limits; they are not token-denominated billing controls or a guarantee of free provider access. Per-run output and context caps remain enforced by the provider adapter.

## Evidence and privacy boundaries

- Retrieval is lexical with a small domain-synonym vocabulary; no embedding/reranking service is required. It is bounded to recorded, scheme-linked evidence. Empty results mean unresolved information, not proof that a benefit does not exist.
- A matching source quotation establishes its location in a stored snapshot. It does not establish current applicability, semantic correctness, document authenticity, official eligibility, or an award guarantee.
- The plan is a research shortlist. Even a passed match covers only recorded rules. Extraction/OCR conditions, additional official terms and unknowns still require review.
- Shared listing excerpts never expand into other cards. Large linked documents may be limited to previously cited spans. Legacy quotes lacking offset/hash binding are excluded.
- `checkOfficialSource` now provides bounded byte comparisons for registered sources (see below). Stored quotes and recorded verification dates remain separate from those observations. General web discovery and new-policy interpretation are not implemented.
- Profile inputs are copied into a private per-investigation context; the durable service stores only the nine supported eligibility fields separately from graph state. The matcher returns aggregate statuses and names of missing fields, not raw answers, names, income values or documents. Derived statuses can still reveal information; cloud inference is not fully local. The UI only sends optional details after opt-in, discloses temporary storage, and never reads or updates a saved account profile.
- A live provider receives the research goal and model-facing tool results. The start action explains this before submission. Student documents, filenames and raw OCR must stay out of goals, model prompts and telemetry. Draft inputs are not written to browser storage or URLs; only opaque run IDs appear in links.
- No global saved-profile writes, bookmarks, reminders, official submissions or catalogue publishing occur. `finishInvestigation` prepares a result; the durable service retains it in the owned run until expiry. Separately saving a research result as a user-confirmed plan remains a later increment.
